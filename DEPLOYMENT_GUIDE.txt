DEPLOYMENT GUIDE - Multi-Device Demo Setup
===========================================

This guide will help you deploy the Siddu Power Project (Sports Stat Tracking App) 
so it can be accessed from multiple devices for demos.

Current Limitations:
-------------------
- SQLite database is file-based (only works on one device)
- Hardcoded secret key (not secure for production)
- Runs on localhost only
- No environment variable configuration

To make this work on multiple devices, you need to:

OPTION 1: Quick Demo (Same Network)
------------------------------------
Good for testing on devices connected to the same WiFi.

Steps:
1. Change the host in main.py from localhost to 0.0.0.0:
   Line 675: uvicorn.run(app, host="0.0.0.0", port=8000)

2. Find your Mac's IP address:
   Terminal: ipconfig getifaddr en0

3. Start the server:
   uvicorn main:app --reload --host 0.0.0.0 --port 8000

4. On other devices on the same network, access:
   http://YOUR_MAC_IP:8000

Limitations:
- Database is still local SQLite (only one device writes to it)
- If your Mac goes to sleep, the app stops
- Not secure for production use
- Suitable only for temporary demos


OPTION 2: Cloud Deployment (Recommended for Real Demos)
--------------------------------------------------------
Deploy to a cloud platform so it's accessible from anywhere.

Recommended Platforms (Free Tier Available):
- Render (render.com) - Easiest for Python/FastAPI
- Railway (railway.app) - Simple, good for PostgreSQL
- PythonAnywhere (pythonanywhere.com) - Free tier available
- Fly.io (fly.io) - Global deployment

Step-by-Step for Render (Easiest Option):

1. Create a GitHub repository (already done)
   Repository: https://github.com/poudel2028-coder/siddupower_projecttrue.git

2. Add deployment files to your project:

   A. Create requirements.txt (already exists, but verify):
      fastapi==0.104.1
      uvicorn==0.24.0
      sqlalchemy>=2.0.36
      passlib==1.7.4
      bcrypt==4.0.1
      python-multipart==0.0.6
      jinja2==3.1.2
      itsdangerous==2.1.2
      psycopg2-binary==2.9.9  # Add this for PostgreSQL

   B. Create a Dockerfile (optional, but recommended):
      FROM python:3.12-slim
      WORKDIR /app
      COPY requirements.txt .
      RUN pip install -r requirements.txt
      COPY . .
      CMD ["uvicorn", "main:app", "--host", "0.0.0.0", "--port", "8000"]

   C. Update main.py to use environment variables:
      - Replace hardcoded secret key with os.getenv("SECRET_KEY")
      - Update database URL to use PostgreSQL from env var

3. Sign up for Render (render.com):
   - Connect your GitHub account
   - Click "New +" -> "Web Service"
   - Select your siddupower_projecttrue repository
   - Configure:
     * Name: siddupower-project
     * Region: choose nearest to you
     * Branch: main
     * Runtime: Python 3
     * Build Command: pip install -r requirements.txt
     * Start Command: uvicorn main:app --host 0.0.0.0 --port $PORT

4. Add a PostgreSQL database on Render:
   - Click "New +" -> "PostgreSQL"
   - Name: siddupower-db
   - Region: same as your web service
   - After creation, copy the Internal Database URL

5. Add Environment Variables in Render:
   - Go to your web service settings
   - Add these environment variables:
     * SECRET_KEY: generate a random string (use: python -c "import secrets; print(secrets.token_urlsafe(32))")
     * DATABASE_URL: (from PostgreSQL database) Format: postgresql://user:password@host:port/dbname

6. Update database.py to use PostgreSQL:
   Change the SQLite connection to:
   DATABASE_URL = os.getenv("DATABASE_URL", "sqlite:///sports_stats.db")
   engine = create_engine(DATABASE_URL)

7. Push changes to GitHub:
   git add .
   git commit -m "Add deployment configuration"
   git push

8. Render will automatically deploy. Your app will be at:
   https://siddupower-project.onrender.com

9. Access from any device using the Render URL.


OPTION 3: Railway Deployment (Alternative)
-------------------------------------------
1. Sign up at railway.app
2. Click "New Project" -> "Deploy from GitHub repo"
3. Select your repository
4. Railway will detect it's a Python project
5. Add a PostgreSQL database:
   - Click "New" -> "Database" -> "Add PostgreSQL"
6. Railway will provide DATABASE_URL in your environment variables
7. Add SECRET_KEY as an environment variable
8. Deploy and Railway will give you a URL like: https://siddupower-project.up.railway.app


OPTION 4: PythonAnywhere (Free Tier)
------------------------------------
1. Sign up at pythonanywhere.com
2. Create a "Web" app
3. Choose Python 3.12
4. Set up a virtual environment
5. Clone your repository
6. Install requirements
7. Configure WSGI file to run uvicorn
8. Set up a PostgreSQL database (via "Databases" tab)
9. Configure environment variables
10. Your app will be at: yourusername.pythonanywhere.com


REQUIRED CODE CHANGES FOR CLOUD DEPLOYMENT
==========================================

1. Update main.py (line 16):
   OLD: app.add_middleware(SessionMiddleware, secret_key="your-secret-key-change-this-in-production")
   NEW: 
   import os
   app.add_middleware(SessionMiddleware, secret_key=os.getenv("SECRET_KEY", "dev-secret-key"))

2. Update database.py:
   OLD: DATABASE_URL = "sqlite:///sports_stats.db"
   NEW:
   import os
   DATABASE_URL = os.getenv("DATABASE_URL", "sqlite:///sports_stats.db")
   engine = create_engine(DATABASE_URL)

3. For PostgreSQL, update main.py line 16 to use secure cookies:
   app.add_middleware(
       SessionMiddleware, 
       secret_key=os.getenv("SECRET_KEY"),
       https_only=True  # Set to False for development
   )


TESTING YOUR DEPLOYMENT
========================

1. After deployment, test locally:
   curl https://your-app-url.com/

2. Test from multiple devices:
   - Phone: open browser and go to your URL
   - Tablet: open browser and go to your URL
   - Another computer: open browser and go to your URL

3. Test database persistence:
   - Create an account on one device
   - Log in on another device
   - Verify data is shared


COMMON ISSUES & SOLUTIONS
==========================

Issue: "Address already in use"
Solution: Kill process on port 8000: lsof -ti:8000 | xargs kill -9

Issue: Database connection errors
Solution: Verify DATABASE_URL is correct in environment variables

Issue: Session not persisting
Solution: Check SECRET_KEY is set and consistent across deployments

Issue: Static files not loading
Solution: Ensure static directory is included in deployment

Issue: CORS errors
Solution: Add CORS middleware if accessing from different domains
